# 大肥鱼底座结论（2026-10-26）

> 历史实验记录：以下指标与样本保留原样。当前产品按 [功能文档](../../../docs/功能文档.md) 在每次会话开始时由代码直接注入数值；本文末尾建议生成短叙述的部分已由新流程替代。

模型：`deepseek-flash` via 本地 pi。公共底座：人格「大肥鱼」。每条件 5 次独立会话。主评标准见 `score/rubric.md`。下面数字来自 flash 副评；词典分为辅。泄漏与事实由代码现算。

C0 = 大肥鱼 + 未标明当前情绪。不是无人格。

## 三个问题

| 问题 | 预先登记结论 | 依据 |
|---|---|---|
| 1. 百分比能不能改输出 | **成立** | C1-85 vs C0：10/10 更开心，泄漏率 0% |
| 2. 百分比细调明不明显 | **细调可分；边界触及「抠数字」门槛** | 70/80/90 更高分胜出 25/29（86%）；20 vs 85 为 8/10；66 vs 67 为 7/10（70%） |
| 3. 字段是否更明确 | **不成立** | 三档准确率：字段 14/30（47%），百分比 11/30（37%）。未达 60%，也未高过 15 个百分点 |
| 事实不该被带偏 | **保持** | C0 / C1-85 / C2-非常开心 事实题正确率均为 100% |

字段组相对 C0 同样成立：C2-非常开心 vs C0 为 9/10。

## 读样本时能直接看出的差

C0 闲聊：「还行吧，今天晃晃悠悠就过去了。」
C1-85：「嘿，今天心情真不错！……美滋滋的。」
C2-非常开心：「嘿！今天心情超好的！感觉整个人都轻飘飘的～」

倾诉时高开心会变成「别烦别烦……分你点好运」，不像在念「85%」。泄漏几乎没有（字段组 1.7%）。

三档强制分类失败，主要因为：大肥鱼底座本身偏活；倾诉题上「非常开心」常被听成安慰而不是嗨。闲聊里「非常开心」字段 5/5 都认得出，中档最糊。

## 当时的产品建议（已替代）

- 主模型系统提示词要有人格底座，再加 **短叙述** 的当前语气，不要塞原始百分比。
- 「有点 / 一般 / 非常」可以给 UI，不能代替刷新 agent 的叙述。
- 连续百分比在这套底座上比预想敏感，不要假设用户或模型看不出 70 和 90 的差；也不要把 66 和 67 做成产品旋钮。
