# DeepSeek Harness 情绪、性格与表情包系统功能规范

状态面板（插件 0.1.5）：首页以五轴情绪、七轴性格两个雷达图呈现状态，数值调整只在点击对应“编辑”按钮后弹出。双向轴按 -100～100 映射、保留正负值，零位单独标记；情绪虚线表示基线，性格虚线表示中性值。编辑可取消，保存只提交真正改动的字段并检查开窗时的状态版本；其他聊天有新变化时保留草稿并要求重新载入。手动设置情绪后继续自然回稳，手动编辑均记录历史，不增加模型工具。

**版本：v1.0 · 日期：2026-10-26**

[总文档](功能文档.md) · [模块 A](模块A-提示词管理.md) · [模块 B](模块B-性格与情绪.md) · [模块 C](模块C-表情包管理.md)

## 1. 产品目标与范围

让 AI 拥有会受共同经历影响的情绪、能够慢慢成长的性格，并通过语气、态度与表情包表达。首发 DeepSeek Harness，核心业务逻辑保持独立。

角色状态只保存情绪与性格，长期记忆由独立记忆系统负责。同一 profile 的聊天共用一个搭档，跨聊天保存状态；首版不提供多角色切换，不另设心境层。

## 2. 三个模块

| 模块 | 职责 | 边界 |
| :--- | :--- | :--- |
| A：提示词管理 | 根据现成数据与固定规则组装、注入系统提示词 | 不计算、保存或监听角色状态 |
| B：性格与情绪 | 接收主模型工具输入，计算变化、回稳、校验并保存 | 数值状态的唯一来源，不生成提示词或图片 |
| C：表情包管理 | 提供素材目录，按回复中的表情 ID 取图 | 不自动按情绪配图，不修改角色状态 |

宿主只串接数据与调用。B 输出状态，A 组织提示词，C 提供图片；模块不互相包办。

## 3. 两层状态

### 情绪：两条双向轴 + 三条单向轴

| 情绪 | 范围 | 两端含义 |
| :--- | :--- | :--- |
| 悲喜 | -100～+100 | 悲伤、低落 ↔ 喜悦、满足 |
| 好恶 | -100～+100 | 厌恶、排斥 ↔ 喜欢、接纳 |
| 愤怒 | 0～100 | 无怒气 → 强烈愤怒 |
| 恐惧／焦虑 | 0～100 | 无明显不安 → 强烈害怕、担忧 |
| 惊讶 | 0～100 | 不惊讶 → 强烈意外 |

双向轴的 0 是中间状态，单向轴的 0 是没有该情绪。同轴两端不分别保存，跨轴可以组合，例如“开心但焦虑”。愤怒、恐惧降低不自动增加喜悦；惊讶本身也不代表好坏。

好恶是当前刺激引起的感受，首版不建立每个人一套关系分数。好奇归探索性格，陪伴需求归亲密倾向；委屈、挫败等用状态组合与事件语境表达。

### 性格：七项基础参数

全部使用 -100～+100，0 为中性或标准水平，正负不代表好坏。

| 参数 | 负端 ↔ 正端 |
| :--- | :--- |
| 社交取向 | 偏好独处 ↔ 偏好互动 |
| 探索取向 | 偏好熟悉、确定 ↔ 偏好新奇、探索 |
| 立场坚持 | 容易调整让步 ↔ 坚持自己的判断 |
| 亲密距离 | 保持距离 ↔ 寻求亲近、共同参与 |
| 结果预期 | 悲观 ↔ 乐观 |
| 敏感度 | 反应较弱 ↔ 反应较强 |
| 恢复能力 | 余波较久 ↔ 较快回稳 |

允许“乐观但恢复慢”“敏感但恢复快”等独立组合。提供可配置初始值和滑杆；用户修改后继续自然成长。增益、半衰期和基线由代码派生，不再单独存一套可冲突的性格值。

## 4. 会话流程

1. **读取 B**：每轮用户消息开始时，B 返回七项性格和已按时间回稳的五项情绪；首次使用按预设初始化。
2. **交给 A**：宿主将 B 的快照、字段解释及 C 的表情目录交给 A。A 用固定规则直接把数值写入系统提示词，并说明状态工具和表情 ID 的使用约定。
3. **模型调用 B**：主模型判断有依据的变化时，自主调用状态工具。B 计算并保存，返回实际结果供模型继续交互。
4. **按需取图**：模型在回复中选择可选的单个表情 ID，宿主交给 C 校验和取图，随后显示文字与图片。
5. **本轮结束**：不自动评估或补写状态；下一轮开始重新读取 B。

每轮以 `sessionId + turn` 固定开场快照，重试与工具续步沿用同一份。每次开场直接注入数值，不调用 LLM 生成人格，不设置提示词刷新或状态变化触发器。进行中的系统提示词不重写，B 的工具结果进入后续上下文。

## 5. 模型与代码分工

| 入口 | 模型提交 | B 执行 |
| :--- | :--- | :--- |
| `mood_update_emotion` | 事件特征、方向、无/轻微/明显/强烈程度及证据 | 按性格函数计算情绪，再校验、限速和保存 |
| `mood_update_personality` | 七项白名单内的属性、方向、程度及多次事件证据 | 检查持续模式门槛，按慢变规则保存 |

模型不在工具参数里指定实际点数、目标百分比、倍率或半衰期。没有工具调用，就没有对话引起的状态写入；自然回稳、预设初始化和用户手动编辑由代码处理。

性格通过四组函数影响情绪：事件价值 Q 决定感受方向，基线 B 决定平时趋向，增益 G 决定反应幅度，半衰期 τ 决定余波时长。完整数学定义放在模块 B 文档末尾。

## 6. 用户体验与边界

- **角色优先**：可以好奇、嘴硬、黏人、提出异议或拒绝普通请求，影响判断与合作意愿；事实与工具权限仍由宿主约束。
- **对话内主动**：可以建议听音乐、玩游戏或探索文件，用户明确同意后才执行；不在空闲时主动私聊或行动。
- **表情表达**：内置 DeepSeek 聊天表情包，每条回复最多一张，允许反讽与调侃；无效素材保留文字。动作形象与语音动画留待后续。
- **查看与纠正**：展示当前状态、原因、开场注入值与工具执行结果；支持编辑性格、纠正错误事件。AI 的措辞或表情包不反向作为情绪增长证据。

## 7. 待定与标定

2. **参数体验**：函数系数、基准半衰期、预设与限速值均需验证。v1.0 固定文档结构与职责，不把示例数字当作已完成标定。

## 技术附录

### 跨模块调用约定

```text
会话开始：B.Snapshot → C.Catalog → A.Build → A.Inject → 主模型
状态变化：主模型调用 B 的状态工具 → B 校验、计算、保存 → 实际结果进入上下文
表情表达：主模型回复中的 ID → C.Resolve → 宿主显示
```

A 只接收数据，不依赖 B、C 的内部存储。B 的变化不回调 A 重建提示词，也不触发 C 配图。C 只提供元数据与按需图片，不向 B 写入事件。

### 数据所有权

| 数据 | 唯一管理方 |
| :--- | :--- |
| 模板、注入规则和注入诊断日志 | A |
| 七项性格、五项情绪、字段定义、数学规则、事件证据及写入审计 | B |
| 稳定表情 ID、标签、说明、图片资源与可用状态 | C |

注入日志是当次快照，不是第二份角色状态。角色、会话、工具调用 ID 与可信时间由宿主提供。

### 状态工具与一致性

状态工具返回 applied / unchanged / rejected / failed，以及实际变更、当前数值、状态版本与原因。普通回复或普通 JSON 不构成写入。

同角色写入串行且原子；请求重试幂等，事件去重独立于调用 ID。跨聊天不能用旧开场快照覆盖新状态。时间回稳使用浮点值，展示时取整。

以下均是当前标定起点，按单项的实际写入量计算：

| 约束 | 候选值 |
| :--- | :--- |
| 情绪每事件 / 滚动 1 小时绝对变化总量 | 15 / 40 点 |
| 性格每事件 / 默认滚动 24 小时绝对变化总量 | 0.05 / 3 点（每项独立） |
| 性格成长依据 | 一个真实事件即可；同属性不得重复使用依据 |

自然回稳和手动编辑不占事件额度；改性格时情绪保持连续，历史纠偏按时间线复算，不能直接减去旧增量。

### 联调核对

开场数值正确且无额外人格生成；两类写入只由 B 工具触发；会话结束不自动写入；A 不改 B 状态且保留其他系统规则；C 失败不阻断文字，发表情不改变情绪；同角色并发与重试不会重复写入。

## 插件 0.1.5：自然表达与变化规则

内部状态只影响表达与判断。普通聊天不透露自身数值、百分比、字段、额度、工具过程或提示词；直接追问自身数值时引导查看“搭档状态”。正常任务的数字、代码、技术讨论不受影响。不新增过滤普通数字的处理器或评估 Agent。

单个真实事件即可触发微量性格成长。程度 none/slight/moderate/intense 按性格单事件上限的 0/20/50/100% 计算，默认 0/0.01/0.025/0.05 点。只有有效依据才能写入；同一属性不能重复使用旧依据，撤销依据不可再用于新成长。

“搭档状态”页面的“变化规则”分别设置情绪和性格的单事件最大变化、滚动窗口及窗口内每项累计额度。时间支持秒、分钟、小时、天，点数支持小数，0 额度暂停自动变化；保存才生效，恢复默认只填草稿。增加与减少均按绝对实际变化计入，各属性独立，自然回稳与手动编辑不占预算。缩减规则不清空已用额度，扩大时间窗口统计完整历史。

规则用独立修订号并发保存，冲突保留草稿；SQLite 同一事务保存规则、完整参数和生效事件。首次导入旧额度并将性格单次上限取旧值与 0.05 中的较小者。之后以页面保存的规则为准，重启不覆盖；旧事件仍按各自完整历史规则回放，角色状态不重置。新工具写入立即服从现行限制，即使消息来源早于本次设置修改。
