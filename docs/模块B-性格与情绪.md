# 模块 B：性格与情绪

**版本：v1.0 · 日期：2026-10-26**

[总文档](功能文档.md) · [模块 A](模块A-提示词管理.md) · [模块 B](模块B-性格与情绪.md) · [模块 C](模块C-表情包管理.md)

## 功能职责

将主模型主动提交的定性变化换算为实际状态，管理七项性格、五项情绪及其可追溯的变化。

- 提供按实际时间回稳后的角色快照，以及量程和端点定义。
- 通过 `mood_update_emotion` 接收事件特征，按性格函数计算情绪变化。
- 通过 `mood_update_personality` 接收性格提议，核验真实经历并限制微量成长。
- 统一保存状态、证据、实际写入量和计算规则版本，支持用户纠偏。

## 边界

- B 是数值状态的唯一来源，不生成系统提示词、不选择图片，也不管理长期记忆。
- 模型自主调用两个状态工具；普通回复、JSON 文本和会话结束都不自动构成写入。
- 模型只提交方向、粗粒度程度和依据，不指定点数、目标百分比、倍率或时长。
- 时间回稳、预设初始化和用户手动编辑由代码处理；同角色跨聊天共享，不同角色隔离。
- A 使用 B 的快照，C 使用回复中的表情 ID；A、C 都不能直接改写 B 的内部状态。

## 内部拆分

**状态管理**保存当前性格和情绪，返回只读快照及字段定义；首次使用按预设初始化。

**变化计算**将事件特征、性格及定性档位输入固定函数，得到候选情绪或性格变化。

**约束与审计**执行证据门槛、边界、单次及滚动限速、去重和原子写入，返回实际结果；错误事件按时间线纠正。

## 流程

每轮用户消息开始时，宿主向 B 请求已回稳的快照交给 A。交互中模型主动调用 B 的工具，B 校验、计算并立即保存，将实际结果返回模型；会话结束不再补做评估。

恢复是否区分正面与负面、具体系数和基准半衰期仍待体验标定。下面给出当前可复算的候选方案，不宣称为心理学定律。

## 技术附录

### 参数与工具输入

七项性格基础值范围均为 -100～+100，除以 100 后得到 $P=(S,X,F,I,O,R,K)\in[-1,1]^7$：

| 符号 | 属性 ID | 负端 → 正端 |
| :--- | :--- | :--- |
| S | `social_pref` | 独处 → 社交互动 |
| X | `explore_pref` | 熟悉、确定 → 新奇、探索 |
| F | `stance_firm` | 调整让步 → 坚持自身判断 |
| I | `intimacy_pref` | 保持距离 → 寻求亲近与共同参与 |
| O | `outcome_expect` | 悲观 → 乐观 |
| R | `reactivity` | 反应弱 → 反应强 |
| K | `recovery` | 回稳慢 → 回稳快 |

五项情绪依次记为 $E=(V,A,H,T,N)$，对应 `valence`、`affinity`、`anger`、`fear`、`surprise`。前两项范围为 -100～+100，后三项为 0～100。基线、增益和半衰期由代码派生，不作为另一套独立慢变参数。

| 情绪 ID | 零点与端点含义 |
| :--- | :--- |
| `valence` | -100 悲伤/低落，0 中间，+100 喜悦/满足 |
| `affinity` | -100 厌恶/排斥，0 无明显好恶，+100 喜欢/接纳 |
| `anger` | 0 无怒气，100 强烈愤怒 |
| `fear` | 0 无明显恐惧或焦虑，100 强烈害怕/担忧；两种感受共用一项，语境保留在事件依据中 |
| `surprise` | 0 不惊讶，100 强烈意外；不自带好坏方向 |

同轴两端不分别保存，跨轴可以组合；不把五项相加作为总心情。单向减少到 0 后停止，不产生负恐惧或自动喜悦；不重复保存平和、安定等反向状态。好恶只保留当前刺激依据，不建立每个人一套关系矩阵；好奇属于探索性格，陪伴需求属于亲密倾向。正负方向不代表道德好坏，性格 0 表示中性或标准水平。

#### 工具职责

情绪与性格两类写入均由正在对话的主模型主动调用工具触发，不新增独立评估模型或会话结束后的自动写入任务：

| 工具 | 接收内容 | 处理结果 |
| :--- | :--- | :--- |
| `mood_update_emotion` | 事件 ID、特征、方向、程度、原因及证据 | 按性格函数计算情绪，校验、限速后保存 |
| `mood_update_personality` | 性格属性、方向、程度、原因及真实事件证据 | 一个有效依据即可，按慢变规则保存 |

插件 0.1.5 的性格工具支持 `mode=inspect`：只提交 `attribute_id`，只读返回最近最多 6 条有效、尚未用于该属性的情绪事件摘要（每条最多 120 字符）和真实来源 ID；不返回用户消息或工具输出原文，不改变数值、版本与额度。历史查询可选；单个有效真实事件即可微量成长，不要求先查历史。实际写入使用 `mode=update`（可省略）及全部定性判断字段；缺字段、数值输入或重复依据仍被拒绝。保持两个模型工具，不新增记忆模块。

角色 ID、会话 ID、工具调用 ID 与时间来源由宿主确定，模型只能引用可核实的事件证据。状态工具在代码中校验并原子保存，返回 `status`（applied / unchanged / rejected；基础设施故障走宿主工具错误通道）、实际变更、当前状态、状态版本及原因。模型以实际返回为准，口头宣称或普通 JSON 文本不构成写入。

重试同一请求应返回已确认结果，不再次增减；事件去重独立于请求去重，换一个工具调用 ID 不能重复领取同一事件的变化。没有调用工具时，不自动推断状态写入；自然回稳和用户手动编辑保留。

#### update_emotion：情绪事件

工具参数采用以下结构，LLM 不直接提议情绪增量：

```json
{
  "event_id": "evt_invitation",
  "features": [
    {
      "feature_id": "interaction",
      "direction": "positive",
      "intensity": "moderate",
      "reason": "用户明确邀请角色一起进行一段较长的闲聊",
      "evidence": ["evt_invitation"]
    }
  ]
}
```

| 特征 ID | `negative` 端 | `positive` 端 |
| :--- | :--- | :--- |
| `outcome` | 已记录目标受损、任务失败、实际损失 | 目标达成、任务成功、实际收益 |
| `interaction` | 明确获得独处、安静处理事情的机会 | 明确增加社交、交流参与的机会 |
| `novelty` | 明确转向熟悉、常规、已验证事物 | 明确接触新奇、未知、需要探索的事物 |
| `closeness` | 明确拉开距离、减少共同参与 | 明确靠近、接纳、增加共同参与 |

以下四项从插件 0.1.3 起只接受 `present` / `relieved`，不接受 `positive` / `negative`，避免把“坏事”误解成“减少该情绪”：

| 特征 ID | `relieved`：缓解／解除 | `present`：发生／加重 |
| :--- | :--- | :--- |
| `obstruction` | 已确认障碍排除 | 明确行动受阻、持续尝试无法推进 |
| `conflict` | 有证据的冲突修复、冒犯澄清 | 有证据的冒犯、敌意、对抗性冲突 |
| `threat` | 已确认威胁解除、风险消退 | 有事实依据的威胁、风险增加 |
| `unexpectedness` | 新解释消除了已有预期落差 | 事实明显超出已记录预期 |

前四项的 `positive` / `negative` 映射为 $d=+1/-1$；后四项的 `present` / `relieved` 同样映射为 $d=+1/-1$。程度由下表换为 $m$，形成 $u_i=d_i m_i$。未标注项为 0，八项组成事件向量 $u$。这是事件输入，不是新状态层；方向描述事实，不预先代表喜欢或讨厌。

例如明确受到冒犯使用 `conflict/present`；有依据的和解使用 `conflict/relieved`，默认分别增加／降低愤怒。SDK 的互斥输入分支和 B 的运行时校验同时限制方向，含糊旧输入被拒绝且不占用事件或变化额度。数值公式不变；已保存的旧记录在历史回放中沿用原解释，不根据理由文本自动改写历史。

| 程度 | 枚举 | 事件特征强度 m | 性格慢变基础点数 |
| :--- | :--- | :---: | :---: |
| 无 | `none` | 0 | 0 |
| 轻微 | `slight` | 0.2 | 单事件上限 × 0.2（默认 0.01） |
| 明显 | `moderate` | 0.5 | 单事件上限 × 0.5（默认 0.025） |
| 强烈 | `intense` | 1 | 单事件上限（默认 0.05） |

主模型在工具参数中描述事实、任务目标、必要背景和工具结果，不先按自身性格计算情绪结论；工具内部不再调用另一个 LLM 标注。由于主模型已读到自身状态，这是一项接口要求，不宣称它与性格信息隔离；数值映射只由代码执行一次。

同一事件同一特征至多一条；重复、自相矛盾、未知特征、数字值或直接情绪增量须校验拦截并记录诊断。“没有聊天”不等于独处奖励，“没有新增风险”不等于威胁解除；失败不自动附加强烈受阻，纠错不自动等于冒犯，道歉不自动等于修复。已生气、继续担忧及 AI 自己的措辞或表情包，都不是新的事实证据。

#### update_personality：性格慢变

```json
{
  "attribute_id": "explore_pref",
  "direction": "positive",
  "intensity": "moderate",
  "reason": "连续多次主动深挖底层原理",
  "evidence": ["evt_001", "evt_004", "evt_007"]
}
```

属性仅接受七项基础值，方向和程度沿用上述枚举；原始变化为 $\Delta P^{raw}=dM_T$，再执行经历门槛、限速及边界。LLM 不输出实际增量、目标百分比、倍率、小时数或基线。情绪工具不会顺带修改性格，性格变化必须由本工具单独触发。

### 数学函数与数值例子

定义 $\operatorname{clip}(x,l,h)=\min(h,\max(l,x))$，$\operatorname{sgn}(0)=0$。

#### 事件价值 Q

插件 0.1.4 的默认反应规则为 v2，中性性格也保留事件基础响应：

$$Q_V=\operatorname{clip}(u_{outcome}+(0.4+S)u_{interaction}+(0.2+X)u_{novelty}+(0.5+I)u_{closeness},-1,1)$$

$$Q_A=\operatorname{clip}(0.3u_{outcome}+0.5(0.6+S)u_{interaction}+0.5(0.2+X)u_{novelty}+(0.5+I)u_{closeness},-1,1)$$

$$Q_H=\operatorname{clip}(u_{conflict}+0.5u_{obstruction},-1,1),\quad Q_T=u_{threat},\quad Q_N=u_{unexpectedness}$$

基础项只在事件发生时起作用，不改变下面的长期基线 B。中性不再等于没有互动、亲近或新奇反应；极端性格仍可改变方向。对应配置为性格权重的 `offset`（-1～1），最终系数为 `amount × (offset + 性格/100)`。显式覆盖某条权重时，需同时提供所需的 offset。立场坚持 F 的情绪系数仍为 0，仅影响判断与合作。

v1 旧规则没有基础项。升级按时间线新增 v2 配置生效点，先结算旧规则的自然恢复，保留当下数值；旧事件仍按其历史完整配置计算，不从新版默认值补入系数，也不倒算过去的零变化。撤销、重算、延迟事件和重启均沿用对应时间段的规则。

#### 基线 B 与增益 G

$$B(P)=(20O,0,0,0,0)$$

$$G_j(P,u)=\operatorname{clip}(1+\alpha_jR+\beta_jO\operatorname{sgn}(Q_j),0.5,1.5)$$

| 情绪项 | 敏感度系数 α | 结果预期修正 β | 基准半衰期 τ⁰ |
| :--- | :---: | :---: | :--- |
| 悲喜 | 0.30 | 0.20 | 4 小时 |
| 好恶 | 0.40 | 0 | 6 小时 |
| 愤怒 | 0.50 | 0 | 2 小时 |
| 恐惧／焦虑 | 0.50 | 0 | 2 小时 |
| 惊讶 | 0.25 | 0 | 5 分钟 |

乐观偏置悲喜基线，并在此候选映射中略放大正向、减弱负向刺激；不自动提高恢复能力。其余基线先为 0，不从黏人推导“喜欢所有人”、从内向推导持续焦虑、从固执推导持续愤怒。增益始终为正，只调幅度。

#### 事件反应与时间恢复

$$\Delta E_j^{raw}=10G_j(P,u)Q_j(P,u),\qquad \tau_j(P)=\tau_j^0 2^{-K}$$

$$E_j(t+\Delta t)=B_j(P)+[E_j(t)-B_j(P)]2^{-\Delta t/\tau_j(P)}$$

所有特征为 0 时，事件增量为 0；自然回稳仍可发生。原始增量最多 15 点，还须执行后续限速。时间与半衰期采用同一单位。K 从 -1 到 +1 时，半衰期从基准的 2 倍缩短到一半；O、R 不改变半衰期。

该候选函数加快所有偏离基线的回稳，包括喜悦与好感；是否只加快负面情绪尚待决定。恢复是趋近自身基线，不是改写事实记忆。各情绪独立更新，不以已有怒气自动追加悲伤或恐惧。

#### 数值例子

其他参数及特征为 0，未触发限速或边界：

| 输入与性格 | 结果 |
| :--- | :--- |
| 互动机会 u=0.5；S=0 | 悲喜 +2，好恶 +1.5；中性保留基本反应 |
| 互动机会 u=0.5；S=+0.8 / -0.8 | 悲喜变化 +6 / -2；好恶 +3.5 / -0.5 |
| 受挫 outcome=-0.5；O=+0.8 / -0.8 | 悲喜基线 +16 / -16；变化 -4.2 / -5.8；恢复能力相同则半衰期相同 |
| 冲突 u=0.5；R=0.8，K=1 | 愤怒增加 7，半衰期 1 小时；4 小时后余波约 0.44 |
| 同样冲突；R=-0.8，K=-1 | 愤怒增加 3，半衰期 4 小时；4 小时后余波 1.5 |

### 更新顺序、预算与纠偏

以下为 `mood_update_emotion` 的处理顺序：

1. 按角色串行、按事件时间顺序处理。先用该时间段内生效的性格计算回稳，得到事件前状态 $E_j^-$。
2. 校验证据、去重，计算 u、Q、G 与原始增量。保存采用的语义标注，重试不能重复写入事件。
3. 设过去滚动 1 小时该项实际事件写入量的绝对值之和为 $C_j$，剩余额度为 $r_j=\min(15,\max(0,40-C_j))$。
4. 写入 $E_j^+=\operatorname{clip}(E_j^-+\operatorname{clip}(\Delta E_j^{raw},-r_j,r_j),L_j,U_j)$。双向边界为 (-100,100)，单向为 (0,100)。预算只记录实际变化 $E_j^+-E_j^-$。

`mood_update_personality` 独立处理性格慢变：单个真实事件即可，默认单项每次最多 0.05、滚动 24 小时绝对变化总量最多 3。上限和窗口均可在页面修改，各属性独立累计。同一事件的情绪计算使用其发生时生效的性格版本；新性格用于之后的事件与时间段，不能通过调换工具调用顺序倒推重算同一事件。事件时间和版本由宿主记录，不由模型任意指定。

自然回稳和手动编辑不消耗事件变化预算。手动编辑性格时，先用旧参数结算到编辑时刻，保持该瞬间情绪连续，再启用新基线与半衰期。所有计算保留浮点精度，仅展示时取整。

时间差不得为负；迟到事件需从历史快照复算。纠正旧事件时重算衰减、后续额度及状态，不能直接减去历史未衰减增量；依赖该事件的性格慢变依据标记复核。保存参数生效时间及规则版本，规则改动须版本化。

给定相同事件向量、性格快照、时间线及规则版本，数值可复算；没有事件和参数变更时，查询频率不改变回稳结果（容许浮点误差）。这不保证 LLM 的语义标注一定正确，因此保留用户纠错入口。

### 状态读取与接口伪代码

开场快照可由 B 作为只读时间投影提供，不占事件额度，不依赖后台计时器。每次工具写入以 B 最新持久化状态为准，不用旧开场快照覆盖其他会话的新提交。

以下为业务接口规划，不约束实际开发语言。

```go
type StateSnapshot struct {
    RoleID      string
    Version     int64
    At          Time
    Traits      map[string]float64
    Emotions    map[string]float64
    Definitions map[string]ParameterDefinition
}

type ParameterDefinition struct {
    Name      string
    Min, Max  float64
    Endpoints map[string]string // 负端、零点和正端的含义
}

type StateChangeResult struct {
    Status        string // applied、unchanged、rejected 或 failed
    State         StateSnapshot
    ActualChanges map[string]float64
    Reason        string
}

func (AffectEngine) Snapshot(roleID string, at Time) (StateSnapshot, error) // 提供指定时刻回稳后的状态快照及配套的量程、端点定义。
func (AffectEngine) ApplyEmotion(ctx CallContext, input EmotionInput) (StateChangeResult, error) // 接收情绪工具的事件特征，经公式、校验和限速后保存并返回实际结果。
func (AffectEngine) ApplyPersonality(ctx CallContext, input TraitInput) (StateChangeResult, error) // 接收性格工具的定性提议，通过经历门槛与慢变限制后保存。
```

`CallContext` 的角色、会话、工具调用 ID 和时间由宿主提供。模型提交 EmotionInput/TraitInput，对应上面的两个 JSON 工具参数；字段定义随快照提供给 A，不是提示词正文。

### 数据与验证

| 实体 | 保存内容 |
| :--- | :--- |
| RoleState | 角色、七项性格、五项情绪、结算时间及状态/规则版本 |
| EmotionDefinition / DynamicsConfig | 轴类型、量程、端点、事件字典、档位、公式、系数、半衰期和限速 |
| EventRecord / EventAppraisal | 宿主事件 ID、时间、事实、发生时性格版本、采用的定性标注与证据 |
| ChangeProposal | 性格目标属性、方向、程度及持续经历依据 |
| StateTransition | 回稳前后值、原始反应、截断原因、实际写入量与预算 |
| StateToolCall | 宿主调用 ID、角色与会话、工具参数、去重依据、执行状态及结果 |

同角色写入串行且原子。重试同一调用幂等；换调用 ID 不能重复领取同一事件的变化。失败保留已确认状态，模型以工具返回为准。

核对：非法数值与未知字段被拒绝；none 不贡献事件变化；重复事件不重计；单向不为负；同轴两端互斥、跨轴可组合；同一输入在不同性格下有不同感受；敏感与恢复独立；编辑不跳变；无刺激不重复增长；查询频率不影响回稳结果；迟到事件和历史纠偏可按版本复算。

### 插件 0.1.0 实现约定

- 工具程度为 `none / slight / moderate / intense`，分别映射情绪特征 `0 / 0.2 / 0.5 / 1`，性格变化 `0 / 0.1 / 0.25 / 0.5`。拒绝数字、未知字段与模型指定时间。
- 证据仅由宿主接纳的真实用户消息和实际外部工具结果产生。支持 `current_user_message`、`last_tool_result` 别名；自己的表述、表情、本插件结果及包装这些结果的工具传输均不构成新证据。
- 一个源事件只接纳一次情绪标注。性格同一属性需要至少三个未用于该属性的不同事件，不能换序或追加一个旧依据反复累积。代码校验存在性与次数，不能机械证明语义理由真实；面板提供纠错入口。
- SQLite 默认位于 `<profile>/data/dsh-mood/mood.sqlite`。写事务统一提交状态、实际额度和调用结果；读取状态与版本使用同一个数据库快照。公式版本前缀、参数配置版本与生效时刻进入历史。重启及修改初始值均不重置已有角色。
- 撤销情绪事件按原始定性标注重放后续时间线和额度，关联性格依据标记待复核，既有性格慢变暂保留。手动修改先结算旧参数，当前情绪连续，随后朝新基线回稳。

### 插件 0.1.5 规则接口

Remote 新增 `getRules()` 与 `setRules({expectedRevision, emotion, personality})`。每组包含 `perEvent`、`windowMs`、`perWindow`，返回独立 `revision`；仅供页面使用，不新增模型工具。时间必须为正安全整数毫秒，额度为非负有限数。旧小时／每日配置仅用于首次迁移，之后以 SQLite 保存的页面规则为准。

修改时将规则、完整 DynamicsConfig 和 configuration 生效记录原子提交；当前角色先按旧规则回稳到保存时刻，不发生跳变。新写入立即采用现行限制，来源事件发生时的性格快照仍保留。预算查询按实际窗口和各事件历史投影计额，不再截断为最近一天；改规则不清额度。只撤销指定情绪事件并按历史配置重算，不反减旧的未衰减增量。

上面的当前规则优先于下方 0.1.0 历史实现记录；旧历史采用其保存时的档位和配额。
