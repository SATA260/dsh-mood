# 模块 A：系统提示词管理与注入

**版本：v1.0 · 日期：2026-10-26**

[总文档](功能文档.md) · [模块 A](模块A-提示词管理.md) · [模块 B](模块B-性格与情绪.md) · [模块 C](模块C-表情包管理.md)

## 功能职责

按固定规则将已有状态与表达约定组织为系统提示词，并在每轮用户消息开始时注入。

- 管理提示词模板、字段排布、顺序和本插件提示词块的去重。
- 显示 B 提供的数值、范围和端点解释，说明两个状态工具的使用规则。
- 接收 C 的目录元数据，告诉模型可选表情 ID 及其输出约定。

## 边界

- A 只知道怎么展示数据，不判断情绪或性格为什么变化；回稳、公式、限速及角色状态保存都归 B。
- 数值在每轮用户消息开始时由代码直接填入，不经 LLM 改写，不监听 B 的变化触发刷新。
- 注入只管理本插件自己的内容，不覆盖宿主、用户或其他插件的系统规则。
- 本轮中 B 返回的新状态作为工具结果进入上下文，不重新执行 A 的注入。
- 缺少必要数据时报告明确错误，不伪造数值或自行计算另一份状态。

## 内部拆分

**规则管理**维护固定模板、提示词块标识、排列顺序和规则版本。

**内容组装**将宿主传入的 B 状态、字段定义、C 目录填入模板，不直接访问两个模块的内部存储。

**会话注入**将组装结果放到约定位置，避免重复，并记录当次注入使用的状态版本和模板版本。

## 流程

在 `agent/pre-step` 确认消息获准进入新一轮后，宿主先从 B、C 取到数据；A 组装并注入，然后交给主模型。后续状态写入和取图分别交回 B、C，不由 A 驱动。

## 技术附录

### 数据与接口伪代码

以下为业务接口规划，不约束实际开发语言。

```go
type PromptRule struct {
    BlockID  string // 本插件拥有的提示词块标识
    Template string
    Order    int
}

type PromptBlock struct {
    BlockID string
    Content string
}

func (PromptManager) Build(rules []PromptRule, values map[string]any) ([]PromptBlock, error) // 按固定规则将传入数据填入提示词块。
func (PromptManager) Inject(systemPrompt string, blocks []PromptBlock) (string, error) // 将本插件的提示词块注入指定位置，避免重复并保留其他系统内容。
```

`values` 是宿主传入的只读数据，其中 `state` 来自 B，`stickers` 来自 C。A 可以检查模板变量是否齐全，不重新校准参数量程或修改其来源状态。

### 调用顺序

```go
state := AffectEngine.Snapshot(roleID, now)
catalog := StickerManager.Catalog()
blocks := PromptManager.Build(rules, map[string]any{"state": state, "stickers": catalog})
systemPrompt := PromptManager.Inject(baseSystemPrompt, blocks)
Host.StartModel(systemPrompt, stateTools)
```

### 记录与核对

A 提供模板与注入内容，B 的数据层保存诊断快照：提示词块标识、模板/规则版本、来源 B 状态版本、当次注入时间和内容。诊断记录不作为角色状态来源。

核对重复注入不叠加、其他系统内容不丢失、正负号与单/双向范围正确、每次开场采用 B 最新快照；B 发生工具更新时不触发 A 重建，A 的渲染也不能改变 B 的数值。

### DSH 0.1.0 接入

通过 `ctx.systemPrompt.section()` 注册 `dsh-mood:state` 独立段。按 `sessionId + turn` 保存、复用开场内容；轮内续步和重试不重新读取数值。宿主拒绝的步骤不记录快照。提示词包括七项性格、五项情绪、量程、定性工具规则、近期可引用依据和全部表情 ID。B 的新值只经工具结果进入本轮上下文。
