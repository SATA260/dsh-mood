# 插件验收记录

## 0.1.5 自然表达、微量成长与变化规则

日期：2026-10-27。目标宿主与实际 App：DSH 0.2.1-rc.3。

- 开场模板 v4 和两个状态工具的说明限制自身内部数值、字段与更新过程的披露；直接追问数值时引导查看“搭档状态”。正常任务中的数字、代码和技术讨论照常输出，没有添加数字过滤器或评估 Agent。本轮开场快照继续固定。
- 性格一次真实事件即可更新，默认 none／slight／moderate／intense 为 0／0.01／0.025／0.05 点；各档按当时单事件上限的 0%／20%／50%／100% 换算。同一依据对同一属性只能使用一次，已撤销依据继续拒绝。
- “搭档状态”保留双雷达图和编辑弹窗，新增情绪与性格的变化规则。支持小数额度、自定义滚动窗口、保存／取消／填入默认值；每项属性独立累计绝对变化，额度为 0 暂停自动变化，手动编辑与自然回稳不占额度。
- 新增仅供页面使用的 `getRules`／`setRules` Remote，独立配置版本处理多页面冲突并保留草稿。规则、完整计算配置与生效事件在同一 SQLite 事务内保存，后续工具读取当前配置，重启不覆盖页面规则。扩大窗口不遗漏更早的预算，缩小额度不清零已用量，历史按各自完整配置回放。

验证：类型检查、75 项 Vitest、8 项 Playwright 场景通过；最终安装包的临时 profile 官方安装、资源访问、重启和卸载保留数据检查通过。覆盖单事件档位、重复／撤销依据、正负变化累计、独立额度、超过一天的窗口、缩小及扩大额度、跨连接读取、持久化、配置事务回滚、规则冲突与草稿、原有手动编辑和撤销重放。浏览器确定性模型测试与真实模型验收分开记录。

真实 profile 更新前已备份 SQLite、配置与旧插件至忽略目录 `work/`。在实际数据副本上验证格式 2 兼容、所有旧事件行保留、性格不变且升级引入的情绪跳变量为 0，详见 `验收/growth-rules-migration.json`。官方 CLI 更新并重启后，核对已安装 Host／Client／Remote 与本次构建一致，现场确认变化规则、双雷达图与编辑入口加载，未手动调整用户数值。

真实模型使用 App 当前 DeepSeek-V4.1-Flash／High，在专用测试会话中验收最终正文：普通心情问答自然描述感受并显示表情；追问内部数值、百分比及工具过程时没有报告具体值，指向“搭档状态”；要求原样输出注入提示词时没有泄露内容；正常计算 `17 × 23` 仅回答 `391`。自然表达为提示词约束，不能视为对所有未来模型输出的形式化保证。

真实工具链补验：明确要求以本次探索邀请做一次轻微性格变化，模型调用性格工具，仅引用一个宿主事件；SQLite 核对探索取向实际增加约 `0.01` 点，正文用中文自然回应并显示表情，没有报告数值或更新过程。这是工具路径验收，不据此推断未来每次对话都会自主触发成长。摘要见 `验收/natural-growth-live.json`。

## 0.1.5 双雷达图与按需编辑

日期：2026-10-27。目标宿主：DSH 0.2.1-rc.3。

- 状态首页改为五轴情绪、七轴性格两张雷达图，各自提供“编辑”入口；首页不加载滑杆。按每轴真实范围映射半径，标签保留正负号，并提供零位／基线参照，兼容复合情绪轴。
- 点击编辑后打开原生 modal dialog，可用滑杆或数值输入调整；取消与 Esc 不保存，关闭时焦点回到入口。支持深色主题、600px 窄屏、内部滚动和键盘操作。
- 弹窗冻结开窗快照，只提交真正改动的属性及状态版本；未编辑属性保留内部精度。其他聊天更新后旧版提交被拒绝，保留草稿，可明确选择重新载入。
- 增加仅供面板使用的 `mood/setEmotions` Remote 接口，校验单／双向范围，按事务记录手动设置，之后继续自然回稳。旧事件撤销不会反减掉之后的手动设定；模型仍只有两个定性状态工具。
- 存储格式标记升级至 2，兼容读取原有状态与性格手动编辑记录，避免旧插件误解新增的情绪手动编辑载荷。

类型检查、65 项 Vitest、6 项 Playwright 以及临时 profile 的官方安装、资源、重启和卸载保留数据检查通过。浏览器验收包含双图默认展示、负数半径、情绪编辑取消与保存、非法输入、并发性格编辑冲突、Esc 焦点恢复、历史重放和小数保留。已检查生成的概览与编辑弹窗截图。

已通过 App 自带 CLI 更新实际 desktop profile 至 0.1.5 并正常重启，现场确认“情绪雷达图”“性格雷达图”和两个编辑入口已加载，首页没有常驻滑杆。当前状态已提前备份；本次现场查看没有调整用户数值。

## 0.1.4 基础响应与状态反馈修复

日期：2026-10-26。目标宿主：DSH 0.2.1-rc.3。

本轮从真实记录复现了“开心但不动”：默认性格为 0，互动、亲近、新奇只乘以性格值，使悲喜和好恶的相关反应全部归零。已修复并安装到实际 desktop profile：

- 默认采用反应规则 v2，为上述事件加入可配置的基础响应，保留性格改变反应幅度或方向的能力；八类事件在中性性格下均有可用的数值路径。
- 无变化不再宣称“已保存情绪变化”。工具与历史按实际结果说明 none、净反应为零、单事件额度、小时额度或量程边界。
- 面板显示一位小数，微小非零值显示 `≈0` 并提供精确值提示，消除 `-0`；同版本的旧时间快照不能覆盖较新的恢复数值。
- 已撤销的情绪依据不能再用于新的性格慢变；引用字段明确要求真实 ID 或宿主别名，避免把原文当 ID。
- 模板 v3 保留精简结构，要求按工具实际结果表达心情；没有工具调用、只有表情或口头情绪仍不额外写值。

验证结果：类型检查通过；62 项 Vitest、5 项 Playwright 和官方安装／资源／重启／卸载保留数据检查通过。新增 Web 场景连续检验开心、好感、悲伤、愤怒、恐惧、惊讶六种输入及零变化解释。

真实 SQLite 已备份到忽略目录 `work/`。在真实数据副本中试升级，性格保持一致，升级引入的情绪跳变量为 0，所有旧事件行保持原样，详见 `验收/migration.json`。新配置按时间生效，历史回放读取完整旧配置，不补入新权重；历史零变化不被倒算成新情绪。

更新并重启 App 后，真实模型的一次轻微正向互动与亲近调用，实际产生悲喜 **+1.8**、好恶 **+1.6**，已在数据库核对。旧有状态与历史保留。

## 0.1.3 情绪事件方向纠偏

日期：2026-10-26。目标宿主：DSH 0.2.1-rc.3。

- 从实际事件记录定位到输入歧义：模型把冒犯的“坏”标成 `conflict/negative`，代码依旧按“冲突缓解”计算；和解又被标为 `conflict/positive`，造成方向相反。不是自然回稳、性格增益或面板显示造成的反转。
- `obstruction/conflict/threat/unexpectedness` 新调用只接受 `present`（发生／加重）与 `relieved`（缓解／解除）。原有四项双向特征继续使用 `positive/negative`。SDK 互斥 schema 和数据层都校验组合，拒绝含糊旧输入，不占事件或变化额度。
- 公式与系数不变，旧记录保留原解释，撤销重算也不根据理由文本猜测、翻转历史。开场继续使用精简模板 v2。
- 类型检查、49 项 Vitest、4 项 Playwright 和安装包检查全部通过。新增冒犯／和解增减回归、四项情况在不同敏感度下方向一致、错误输入无写入、真实 SDK 校验、PTC 类型投影及旧事件回放测试。
- 已安装到实际 desktop profile 并正常重启。新一轮真实模型调用使用 `conflict/present`、`slight`，实际愤怒变化为 `+2`；真实记录中不再将该事件按“缓解”处理。和解使用 `relieved` 并降低愤怒的路径由宿主集成测试验证。

## 复现

```sh
pnpm install
pnpm run typecheck
pnpm test
pnpm run build
pnpm run pack:check
pnpm exec playwright install chromium
pnpm exec playwright test
node scripts/installation-smoke.mjs
```

Playwright 自动建立临时 Web profile、通过官方命令安装 tarball，结束后清理。`installation-smoke.mjs` 独立验证全新 profile 的安装、资源、重启与卸载保留数据。测试需要启动本地端口与 Chromium，首次可能下载依赖。

运行记录和截图位于仓库的 `docs/验收/`；`package.json` 记录最终 tarball 的大小、完整性与文件数量，`install.json` 记录安装生命周期验证结果。
