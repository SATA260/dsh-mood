# 插件验收记录

## 0.1.4 基础响应与状态反馈修复

日期：2026-10-26。目标宿主：DSH 0.2.1-rc.3。

本轮从真实记录复现了“开心但不动”：默认性格为 0，互动、亲近、新奇只乘以性格值，使悲喜和好恶的相关反应全部归零。已修复并安装到实际 desktop profile：

- 默认采用反应规则 v2，为上述事件加入可配置的基础响应，保留性格改变反应幅度或方向的能力；八类事件在中性性格下均有可用的数值路径。
- 无变化不再宣称“已保存情绪变化”。工具与历史按实际结果说明 none、净反应为零、单事件额度、小时额度或量程边界。
- 面板显示一位小数，微小非零值显示 `≈0` 并提供精确值提示，消除 `-0`；同版本的旧时间快照不能覆盖较新的恢复数值。
- 已撤销的情绪依据不能再用于新的性格慢变；引用字段明确要求真实 ID 或宿主别名，避免把原文当 ID。
- 模板 v3 保留精简结构，要求按工具实际结果表达心情；没有工具调用、只有表情或口头情绪仍不额外写值。

验证结果：类型检查通过；62 项 Vitest、5 项 Playwright 和官方安装／资源／重启／卸载保留数据检查通过。新增 Web 场景连续检验开心、好感、悲伤、愤怒、恐惧、惊讶六种输入及零变化解释。

真实 SQLite 已备份到忽略目录 `work/`。在真实数据副本中试升级，性格保持一致，升级引入的情绪跳变量为 0，所有旧事件行保持原样，详见 `验收/migration.json`。新配置按时间生效，历史回放读取完整旧配置，不补入新权重；历史零变化不被倒算成新情绪。

更新并重启 App 后，真实模型的一次轻微正向互动与亲近调用，实际产生悲喜 **+1.8**、好恶 **+1.6**，已在数据库核对。旧有状态与历史保留。

## 0.1.3 情绪事件方向纠偏

日期：2026-10-26。目标宿主：DSH 0.2.1-rc.3。

- 从实际事件记录定位到输入歧义：模型把冒犯的“坏”标成 `conflict/negative`，代码依旧按“冲突缓解”计算；和解又被标为 `conflict/positive`，造成方向相反。不是自然回稳、性格增益或面板显示造成的反转。
- `obstruction/conflict/threat/unexpectedness` 新调用只接受 `present`（发生／加重）与 `relieved`（缓解／解除）。原有四项双向特征继续使用 `positive/negative`。SDK 互斥 schema 和数据层都校验组合，拒绝含糊旧输入，不占事件或变化额度。
- 公式与系数不变，旧记录保留原解释，撤销重算也不根据理由文本猜测、翻转历史。开场继续使用精简模板 v2。
- 类型检查、49 项 Vitest、4 项 Playwright 和安装包检查全部通过。新增冒犯／和解增减回归、四项情况在不同敏感度下方向一致、错误输入无写入、真实 SDK 校验、PTC 类型投影及旧事件回放测试。
- 已安装到实际 desktop profile 并正常重启。新一轮真实模型调用使用 `conflict/present`、`slight`，实际愤怒变化为 `+2`；真实记录中不再将该事件按“缓解”处理。和解使用 `relieved` 并降低愤怒的路径由宿主集成测试验证。

## 复现

```sh
pnpm install
pnpm run typecheck
pnpm test
pnpm run build
pnpm run pack:check
pnpm exec playwright install chromium
pnpm exec playwright test
node scripts/installation-smoke.mjs
```

Playwright 自动建立临时 Web profile、通过官方命令安装 tarball，结束后清理。`installation-smoke.mjs` 独立验证全新 profile 的安装、资源、重启与卸载保留数据。测试需要启动本地端口与 Chromium，首次可能下载依赖。

运行记录和截图位于仓库的 `docs/验收/`；`package.json` 记录最终 tarball 的大小、完整性与文件数量，`install.json` 记录安装生命周期验证结果。
